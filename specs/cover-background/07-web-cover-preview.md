# 07 — 网页封面预览

**What to build:** 改完封面文字模板后点一下按钮，当场看到成品封面长什么样，不必等到下一次下播走完整条上传流程才发现排版有问题。预览用的是与投稿时完全相同的渲染器，所以预览好看就代表实际产出好看。

预览接口不读数据库、只接收显式参数，因此模板页和主播页可以复用同一个接口，各自传自己那一级的值。

背景文件名可以手工填写（例如已用 scp 放好图），因此本票不依赖上传功能，可与 06 并行。

**Blocked by:** 01（需要图片背景渲染能力）、02（需要其建立的集成测试设施）

**Status:** ready-for-agent

- [x] 接口不读取数据库，因此可被多个页面复用
- [x] 接口内部展开占位符、按换行标记切行，复用与投稿时相同的渲染函数，直接返回 JPG 字节

## 落点

- 接口：`GET /v1/cover-preview?template=...&background=...`，返回 `image/jpeg` + `no-store`。
  做成 GET 是因为产出就是一张图，`<img src>` 能直接吃；参数相同但背景图可能刚被换掉，故禁缓存。
- 实现：`server/api/cover_preview.rs`，子路由 `cover_preview_router(root)`——根目录做成参数，
  与 02 的 `static_file_router`、06 的 `cover_background_router` 同一形状。
- 前端：`app/ui/CoverPreviewButton.tsx`（独立组件，供 08 的主播页原样复用）
  \+ `TemplateFields.tsx` 在背景图字段旁挂上按钮。

## 实施中新增的三项（非原定范围）

1. **`Recorder::try_format`：堵住一个能打崩请求的输入。** chrono 对非法时间格式串（例如
   落单的 `%`）不是报错而是 **panic**——`DelayedFormat` 的 Display 返回 Err，`to_string()`
   直接炸。模板此前只来自库里已保存的值，现在却是用户当场敲进输入框的，手滑一个 `%`
   就能打崩请求。新增的 `try_format` 先用 `StrftimeItems` 验一遍再格式化；预览接口据此回 400。
   校验的是**替换之后**的串——主播名、直播标题里也可能带 `%`，只验模板原文会漏。
2. **`format` 改为委托 `try_format`，非法格式串退化成「占位符原样保留」。** 顺带把同一个
   panic 从投稿路径上摘掉了：封面只是稿件的附属品，不值得让一整场录播的提交因为模板里
   一个 `%` 而炸掉整个上传任务。有测试锁住（`format_degrades_instead_of_panicking_...`）。
3. **「单段文件名」这条规则收口到 `path_safety::single_segment_name`。** 此前 `background_path`
   与 `expected_format` 各写了一份，本票要用是第三份。三处必须是同一条规则，否则
   「上传得进去、投稿用不上」这类哑失败迟早从缝里漏出来。

## 四处有意的决定

1. **示例值而非真实主播数据。** 接口不读库（这正是两个页面能复用它的原因），占位符只能拿
   一组示例值展开：`示例主播` / `示例直播间标题`，时间取当前时刻。用户要确认的是排版——
   几行、多长、会不会顶到边——示例值撑起的字数与真实值同量级，够看。
2. **背景文件读不出来时回退纯黑，而非报错。** 与投稿时完全一致，「预览即产出」的承诺
   才成立；用户当场就看见背景没生效。这与 01 的子命令刚好相反（那边 fail-fast），
   因为那是本地调参、悄悄给张黑图更难排查，而这里的首要目标是**保真**。
3. **只有结构性非法才回 400**：越界（穿越/绝对路径/符号链接逃逸）与带目录的文件名。
   后者必须拦——投稿侧只认单段文件名，这里放行就成了「预览好看、投稿黑底」。
   单段检查刻意**不与越界检查合并**：`resolve_within` 对「中间目录不存在」报的是
   `RootUnavailable`，若在那里就返回，`nope/aurora.png` 这类值会绕过单段检查。
4. **渲染丢进 `spawn_blocking`。** 解码 + Lanczos3 缩放 + JPEG 编码是实打实的 CPU 活儿，
   一张 10 MB 的大图能跑上几百毫秒；在 async 上下文里同步跑会占住一个 worker 线程，
   把同期的录播状态推送一起卡住。
