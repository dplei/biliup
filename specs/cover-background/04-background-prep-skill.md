# 04 — 背景图处理 skill

**What to build:** 用户把一张原图交给 Claude，Claude 负责把它变成一张适合压文字的背景图：裁切到目标尺寸、试出合适的压暗与模糊参数、渲染样图并**自己查看效果**、迭代到文字清晰为止，最后输出一张可直接使用的成品图。

这解决的是「我不是做设计的，不知道该压暗多少、模糊多少」——调参的人从用户变成 Claude，而 Claude 能真的看到渲染结果，不是凭空猜。

职责边界要写死在 skill 里，避免它越界。

**Blocked by:** 01（需要能渲染样图的命令行子命令）

**Status:** ready-for-agent

- [x] 仓库内新增 skill，与根目录既有的那个「操作 CLI 工具」的 skill 相互独立、互不干扰
- [x] skill 通过 01 提供的命令行子命令渲染样图，并在迭代过程中实际查看渲染出的图片
- [x] 输出的成品图尺寸为 1146×717，可直接作为背景使用
- [x] skill 明确不从零生成背景图（只处理用户给的图）
- [x] skill 明确不调整字号、行距、边距、文字颜色等排版参数
- [x] skill 明确不上传到服务器、不持有任何生产环境凭据
- [x] 整个流程不依赖本机安装 ImageMagick、ffmpeg 或 Python 图像库
- [x] 用一张实际的图走通一遍完整流程，确认迭代能收敛到文字清晰

## 落点与实施记录

skill 在 `.claude/skills/cover-background/SKILL.md`。`.gitignore` 原本整体忽略 `.claude/`，
skill 无法入库，改为 `.claude/*` + `!.claude/skills/`：只放行仓库级 skill，
`settings.local.json` 等个人配置仍被忽略。

**收敛靠三件事，缺一件就退化成「甩参数表」**：

1. 每轮强制用 Read 打开渲染出的样图，并写出**看到了什么**（哪一行、哪个笔画、被什么干扰）；
2. 三条判据同时约束下限与上限——文字要清楚，但背景还得看得出是一张图，否则等于纯黑底，
   这张图白配了；
3. 「问题 → 调整」对照表把观察翻译成参数动作，一轮只动一个变量。

**实图验证**：一张 1440×810 的暗色宇宙插画（中央有黑洞吸积盘的高光、满屏细星点）。
第一轮 dim 30/40/50 定位到 40 附近，第二轮按「中央高光先加 blur 摊开」换到
`--dim 35 --blur 18`——比单纯压暗更亮、辨识度更高，文字反而更清楚。**两轮收敛**，
回读校验通过，成品 `file` 报 1146×717。

**review 修出四处**：`OUT=$(mktemp -d)` 跨 Bash 调用必然失效（每次都是新 shell），
而它正好卡在标着「不能跳」的回读校验上，现全部改成字面绝对路径并写明原因；第 1 步的
三档原本硬编码 30/45/60，架空了第 0 步按图选起点的表，现改为从起点 ±10 长出；
「服务端对背景图不做任何处理」不准确（仍有适配画布与 JPEG 重编码），已按实际改写；
交付话术原本断言网页表单存在，而 03/05/06/08 都还没做，改为交给用户自行放图。
