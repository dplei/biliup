# 02 — 静态文件接口收口与 HTTP 测试设施

**What to build:** 静态文件接口目前把用户传入的路径直接交给文件服务，等同于任意文件读取——任何人都能顺着它读到服务工作目录之外的文件。本票把它收口到一个统一的路径校验函数上，同时**保证现有功能不受影响**：日志下载和历史记录页的录播视频回放都必须照常工作。

本票另外建立该服务的 HTTP 层集成测试设施，后续的上传接口与预览接口才有地方写集成测试。

**注意**：该接口并非只服务图片，因此**不能**把它收窄到背景图目录——那会直接破坏视频回放与日志下载。只能限定在服务的工作目录内并拒绝穿越。

本票不依赖任何其他票，具备独立的安全价值，可以随时插队优先做。

**Blocked by:** 无——可立即开始。

**Status:** ready-for-agent

- [x] 新增路径校验函数，输入「允许的根目录」与「用户提供的路径」，输出校验后的绝对路径或错误
- [x] 拒绝 `..`，包括百分号编码等变体
- [x] 拒绝绝对路径
- [x] 拒绝解析后落在根目录之外的符号链接
- [x] 静态文件接口改用该函数，根目录取服务的工作目录
- [x] 回归验证：各类日志文件仍可正常下载
- [x] 回归验证：历史记录页的录播视频仍可正常回放（含 Range 请求，拖动进度条依赖它）
- [x] 集成测试目录已建立；**dev-dependencies 段最终未新增**——`tower` 的 `util` 特性本就被非测试代码用到（此前靠依赖特性统一才编得过），显式加在主依赖上即可，再复制一份到 dev 反而多出一处版本号要维护

## 残余风险（已知，未处理）

**TOCTOU**：校验用 `canonicalize`，随后文件服务才真正打开目标，两者之间存在时间窗口，理论上可被换成指向外部的符号链接。录播进程本身就在往工作目录写文件，因此窗口不是纯理论。彻底消除需要原子化的「打开后再验证」（如 `openat` + `fstat` 比对），父 spec 未要求，本票未做。
