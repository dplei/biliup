# 01 — 占位主播信息收成具名构造器

**What to build:** 手动补投反查不到主播的文件时，稿件不再出现用户从未填写过的转载来源。占位信息只保留名字，直播间地址与标题留空——空值一眼可辨「这里没信息」，假值会被原样提交到 B 站。

**Blocked by:** None — can start immediately

**Status:** ready-for-human

- [x] 占位信息由一个具名构造器产出，调用方不再摆位置参数
- [x] 名字取自上传模板名，直播间地址与直播标题留空
- [x] 构造器的文档注释写明这些字段的去向（转载来源兜底值、模板 `{url}` / `{title}` 展开），说清为什么必须留空
- [x] 单测锁住字段映射，断言上标注每个字段的用途
- [x] 反查命中的路径行为不变

## 完成记录

改动落在两处：模型模块新增占位构造器与其单测，历史文件上传端点改为调用它。

行为上只变了两项：转载来源在未显式配置时从字面量 `stream_title` 变为空字符串，
简介/标题模板里的 `{url}` 同样从该字面量变为空。`{title}` 此前就已是空，不变。

## 发现经过

由票 `specs/cover-background/05` 的代码审查顺带挖出。当时新增的逻辑要拿占位信息的
直播间地址去反查主播行，审查指出「它现在不出问题，靠的是另一个 bug」——那个地址恰好是
不可能匹配任何一行的字面量。该处逻辑已改为用「是否反查命中」的布尔值门控，
不再依赖这个字段的取值，因此本票的修复不会反过来影响它。
