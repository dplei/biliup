# 02 — 普查同形状的位置参数构造器

**What to build:** 弄清「相邻同类型参数被位置调用」在本仓库是孤例还是一类问题，并给出结论：哪些地方值得同样收成具名构造器，哪些不值得。

01 修的是一个具体的手滑，本票问的是「还有几个地方能这么滑」。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 找出所有「连续两个及以上同类型参数」的构造器与工厂函数，列出调用点
- [ ] 逐个判断风险：参数值是否会流向外部系统（投稿接口、文件名、数据库），有无测试覆盖该调用点
- [ ] 高风险的（值流向外部且无测试覆盖）给出处理建议：具名构造器、newtype、或补测试
- [ ] 低风险的明确记为不处理，写清理由，避免下次重复评估
- [ ] 结论写成一份清单附在本票末尾；真要动手改的部分另开票，本票只出结论不改代码

## 判断依据

风险不在于「参数多」，而在于三件事叠加：相邻同类型参数（写错顺序仍能编译）、
兜底路径无测试覆盖、值会离开本进程。只满足前一两条的不必动。
