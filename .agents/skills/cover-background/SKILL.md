# 封面背景图调参

用户丢来一张原图，你把它变成一张压得住白字的 1146×717 背景图。

**调参的人是你，不是用户。** 用户不做设计，没法凭感觉说该压暗多少、模糊多少。你必须
把渲染出的样图**用 Read 工具读进来、真的看**，根据看到的效果调 `--dim` / `--blur`，
迭代到文字清晰为止。不看图就报参数、或者把一张参数表甩给用户让他自己试，
等于这个 skill 没有执行。

与仓库根目录的 `SKILL.md`（安装、操作 biliup CLI）无关，两者互不引用、互不干扰。

## 边界

- **不从零生成背景图**：不画图、不调用生成模型、不去网上找图。只处理用户交给你的那张图。
  用户没给图就问他要，不要自作主张造一张。
- **不调排版**：字号、行距、边距、文字颜色、描边宽度都是渲染器里的常量，这条流程碰不到，
  也没有对应的命令行参数。文字压不住只能从背景想办法。
- **不上传**：不碰服务器、不写数据库、不需要任何凭据。产出停在本地一个文件路径上，
  这张图往哪放、配给哪个主播，都由用户自己决定。
- **不装东西**：整条流程只用 `cargo` 和仓库自带的子命令。不需要 ImageMagick、ffmpeg、
  Pillow，**也不要去装**——本机没有它们是有意的。

## 准备

在仓库根目录构建（`SQLX_OFFLINE` 不可省，否则 sqlx 会去连数据库）：

```bash
SQLX_OFFLINE=true cargo build -p biliup-cli
```

产物是 `target/debug/biliup`，后文都用这个路径。**不要用 PATH 里的 `biliup`**——
那多半是装好的旧版本，没有 `cover-preview` 子命令。确认一下：

```bash
target/debug/biliup cover-preview --help
```

样图和成品都写到仓库外的一个工作目录，不要污染仓库。会话有 scratchpad 目录就用它，
否则 `mkdir -p /tmp/cover-bg`。

**这个目录的绝对路径要在每条命令里写死。** Bash 工具每次调用都是全新 shell，
`OUT=$(mktemp -d)` 这类变量下一条命令就没了，`"$OUT/x.jpg"` 会展开成 `/x.jpg`
写到根目录去。原图路径同理，用绝对路径。

## 开工前问清两件事

1. **原图路径**。
2. **封面文字实际长什么样**。这直接影响判断：文字过宽时渲染器会缩字号，把最宽的一行
   收进安全边距（短文字不会被放大，始终是 110px 上限）。所以必须拿**真实的最长一行**
   去试，用「测试」两个字糊弄会得出偏乐观的结论——真上阵时字更小、更难读。
   模板里的占位符要先换成真实值再传给 `-t`：`{streamer}` 主播名、`{title}` 直播间标题、
   `{url}`，以及 `%Y-%m-%d` 这类 strftime 时间格式。用户答不上来就取一个具象的例子
   （最长的那个主播名 + 一个真实日期），并在交付时说明你用的是什么文字。

## 调参循环

### 第 0 步：先看原图

用 Read 打开原图。两件事要判断：

- 它属于下表哪一档，作为参数起点；
- 麻烦在哪：中央有没有高光、亮块、密集纹理、招牌文字。**文字是居中的**，中央那条横带
  才是战场；四角再花也不影响可读性。

另外记住构图会被裁：原图按 `object-fit: cover` 等比缩放到覆盖 1146×717 再居中裁剪，
不拉伸也不留边——两侧或上下会被切掉。看原图时就要想到裁完剩什么。

| 原图 | 起点 |
| --- | --- |
| 暗、平（夜景、渐变、纯色底、大面积单色） | `--dim 20 --blur 4` |
| 中等（室内、风景、单人像） | `--dim 40 --blur 10` |
| 亮、花（雪景、白天街景、合影、带招牌文字、截图） | `--dim 55 --blur 16` |

### 第 1 步：一次渲三档，别一档一档试

三档 = 第 0 步选中那一行的 dim **±10**，blur 用同一行的值固定不动——一轮只动一个变量，
否则看不出是谁的功劳。下面这条按「中等」那一档（`--dim 40 --blur 10`）展开，
起点不同就把数字换掉：

```bash
for d in 30 40 50; do
  target/debug/biliup cover-preview \
    -t '真实主播名\n2026-07-23' -b /绝对路径/原图.png \
    -o "/工作目录/try-dim$d.jpg" --dim $d --blur 10
done
```

（`for` 循环在单条命令里，变量不跨调用，是安全的。）

然后**把三张全部 Read 进来**横向对比，选出最好的一档再微调。三张一起看比一张一张试
收敛快得多，因为你能直接看出差异往哪个方向走。

### 第 2 步：判定与调整

每一轮都要写一句**你看到了什么**——哪一行、哪个笔画、被什么干扰。只写「不够清楚」
说明你没在看图。

三条判据，全满足才算过：

1. 每一行都能一眼读完，包括最细的笔画：数字、标点、括号、英文小写。
2. 文字不是靠描边硬撑。盯笔画中段（不是边缘），背景细节不应该以同等亮度贴着它。
3. **背景仍看得出是一张图。** 糊成一团黑就等于纯黑底，这张图白配了——这是上限，
   和「够清楚」同样重要，别为了保险一路压到 80。

| 看到的问题 | 调整 |
| --- | --- |
| 笔画和背景纹理搅在一起、边缘发毛 | `--blur` +6~10，`--dim` 不动 |
| 背景亮，白字发灰、被背景吃掉 | `--dim` +10~15 |
| 中央有个亮斑/高光正顶着文字 | 先加 `--blur` 把高光摊开，还压不住再补 `--dim` |
| 已经很清楚，但看不出原图是什么了 | `--dim` -10（或 `--blur` -4），回到三条判据重看 |
| 整体够暗但细节很碎、像噪点 | `--blur` +6，`--dim` 不动 |

调整幅度：`--dim` 每次 ±10~15，`--blur` 每次 ±4~8。比这更小的步子肉眼分辨不出来，
白跑一轮。

**上限 4 轮。** 4 轮还收不住就停下，交出当前最好的一版并说明卡在哪。最常见的原因是
原图中央本身明暗对比极端（例如逆光人像、中央有大片纯白），那是选图问题不是参数问题，
建议用户换一张中央更空的图。

### 第 3 步：导出成品背景

```bash
target/debug/biliup cover-preview \
  -t '' -b /绝对路径/原图.png -o /工作目录/cover-bg-final.jpg \
  --dim <定稿值> --blur <定稿值> --background-only
```

`-b` 仍然指向**原图**：参数是在原图上重跑一遍，不是拿样图去二次加工。样图上已经有字了，
拿它当输入会把文字烤进背景。输出也写进工作目录，别用相对路径——那会落在仓库里。

### 第 4 步：回读校验（不能跳）

服务端不做任何图像增强：不压暗、不模糊、不调色，只把背景适配画布后压上文字。成品已经是
1146×717，适配对它是空操作，所以把成品当背景、`--dim 0 --blur 0` 再渲一次，
得到的就是线上产出（只差一次 JPEG 重编码）：

```bash
target/debug/biliup cover-preview \
  -t '真实主播名\n2026-07-23' -b /工作目录/cover-bg-final.jpg \
  -o /工作目录/verify.jpg --dim 0 --blur 0
```

Read `verify.jpg`，它应当与你定稿的那张样图看上去一致。这一步专抓一类错误：第 3 步把
定稿参数抄错、或 `-b` 误指向了样图——两者都会让上传的图与你批准的效果不是同一张。
顺手确认尺寸：

```bash
file /工作目录/cover-bg-final.jpg   # 应包含 1146x717
```

### 第 5 步：交付

报告这些，然后停手：

- 成品背景的路径；
- 定稿的 `--dim` / `--blur`；
- 你用来判断的那行文字；
- 每轮看到了什么、怎么调的（各一句）。

然后把文件交给用户，由他决定放到哪、配给谁。**放图这一步由用户做，不是你做**——
你不碰服务器，也不需要知道他怎么放。（网页上传表单与模板/主播的背景字段是本特性的后续票，
未必已经落地；没落地时用户会按他现有的方式放图，不用你操心。）

## 坑

- `-t` 里的换行写成字面量 `\n`（反斜杠 + n），和网页「封面文字模板」同一种写法。
  shell 里用单引号包住，别让 shell 把它吃掉。
- `--background-only` 必须同时给 `-b`，否则报错——没有原图就没有背景可导。
- 原图读不出来（路径错、不是图片、格式不支持）子命令会直接报错。这是有意的：
  本地调参阶段宁可报错，也不能悄悄给你一张黑图让你误以为参数生效了。
- 每导出一次 JPEG 就多一次有损压缩。所以每一轮都从**原图**重新跑，别拿上一轮的产物
  接着调，画质会一轮轮塌下去。
- `--dim` 取值 0-100（100 全黑），`--blur` 是非负的高斯半径，越大越糊也越慢。这两个参数
  只存在于本地：调出来的效果被烘焙进成品图，不会随图一起传到任何地方。所以参数本身
  没有保存的价值，写进交付报告是为了下次换图时有个起点。
