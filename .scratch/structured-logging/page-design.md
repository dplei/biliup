# 日志与事件页面：初步交互设计

Status: needs-triage
来源：[Issue #2](https://github.com/dplei/biliup/issues/2)、[总体方案](spec.md)，以及本轮关于
信息混杂、无法筛选、颜色不突出、阅读费劲的补充。本轮是设计，不修改应用页面实现。

可交互参考：[日志与事件演示原型](prototypes/log-events-design.html)。文件使用合成数据，
不连接后端；已修复脚本别名冲突并增加重复初始化保护。原型随设计入库，供后续 session
查阅布局与交互，不依赖本机对话附件路径，也不表示应用页面已实现。

## 1. 页面定位

将导航中的「实时日志」调整为「日志与事件」，保留原 `/logviewer` 路径，避免已有书签失效。
页面从文件阅读器变为可以查历史、看异常、追踪整场经过的事件列表。

这里描述目标页面；发布按 [阶段计划](rollout-plan.md) 分开进行：[16](issues/16-preview-ui.md)
先增加「日志与事件（试用）」入口，旧 `/logviewer` 仍默认；[17](issues/17-default-events.md)
才把该路径切为新页，并继续保留旧原始页；[18](issues/18-stop-legacy-writes.md) 停旧写入后
旧页明确显示非实时/已停用。新页面上线不代表旧文件已经退出。

不再按 `ds_update / download / upload` 文件名分 tab。即使所有记录来自同一个主进程，仍
按事件字段区分级别和业务；模块来源只放高级筛选/详情，不再承担主要导航。

迁移期间，新页默认显示原生事件；桥接诊断作为显式来源筛选，标注 `legacy_bridge` 和
缺字段情况，不与原生事件混算覆盖。显示当前接入范围和起始边界：空列表可能意味着该
业务尚未接入，不能让用户误以为没有异常。两套页都应清楚标明数据来源。

沿用现有 Semi 组件和主题，布局分为两个视图：

- **事件日志**：默认入口，普通关键事件、警告、错误共用一套可筛选的列表。
- **运行进度**：录制/预处理/排队/上传等当前状态，覆盖更新。进度不参与事件行数统计。

第一版不增加占满首屏的统计卡片或图表；用户打开页面应尽快看到异常和业务经过。

## 2. 事件日志布局

从上到下：页面名称及连接状态 → 视图切换 → 级别快速筛选 → 业务/主播/时间/搜索 →
命中数与排序 → 事件列表 → 加载历史记录。

顶部的连接状态用于区分「实时连接正常 / 正在重连 / 已暂停刷新 / 仅历史可用」。数据库
写入异常另作明确提示：连接成功不代表持久化成功，零条结果也不代表没有发生错误。

### 筛选

| 条件 | 行为 |
| --- | --- |
| 级别 | 默认 INFO/WARN/ERROR；能分别看信息、警告、错误，并支持 WARN+ERROR 组合；DEBUG/TRACE 在高级选项中 |
| 业务类型 | 系统、录制、上传、投稿、预处理、认证、审计；与级别条件取交集 |
| 主播 | 可搜索选择；系统事件无主播时仍能通过「全部主播」查询 |
| 时间 | 最近 1 小时、24 小时、7 天、自定义起止；显示明确时区，避免把本地时间当 UTC |
| 关键词 | 搜中文摘要、事件名、文件、关联 ID；不能只在已经加载的当前页里找 |
| 更多条件 | 录制场次、投稿会话、分段、尝试、来源模块；默认折叠，避免首屏堆字段 |

不同维度取 AND，同一维度多选取 OR。级别旁的计数采用其余筛选条件下的数量，不是当前
加载页的条数；需要后端聚合支持。如果统计尚未返回，显示加载状态而不是伪造 0。

筛选进入 URL 查询参数，刷新、复制链接和返回页面后可恢复。每次筛选变化清空旧游标；取消
过期请求，不能让慢响应覆盖新条件。查询范围过大时可提示收窄，不在前端默默截断结果。

交互草图使用少量明确标注的演示数据，展示单级别、业务、主播、示例时间段和关键词筛选；
生产的多级别选择、真实时间选择、后端全量搜索不由草图冒充已实现。

## 3. 一条事件怎么读

桌面行优先展示：**毫秒时间 + 严重程度 + 中文摘要**；次行展示业务标签、主播和文件。
正文使用正常界面字体，只有时间、ID、代码使用等宽字体；不把一整段 Rust 调试输出平铺。
小屏改为上下排列，不通过缩小字或必须横向拖动来容纳所有列。

| 级别 | 颜色与强调 | 文案含义 |
| --- | --- | --- |
| 信息 | 正常背景、蓝色小标识，正文保持正常文字色 | 正常关键事件或预期决策 |
| 警告 | 琥珀色标识/左侧细线、很浅的对应底色 | 有异常或非预期降级，目前仍能继续 |
| 错误 | 红色标识/左侧细线、很浅的对应底色 | 本次操作失败，或目标结果无法可靠确认 |

所有级别都显示中文文字和可识别图标，不只靠颜色。浅/深色模式分别采用合适的文字、底色
和边界对比；业务分类使用中性标签，避免录制/上传/投稿各占一种鲜艳颜色争抢注意力。
绿色只在独立结果状态中表示成功，不把所有 INFO 都染绿。

摘要应描述「对象 + 发生什么 + 当前影响」，例如「第 2 段上传请求超时，本次尝试失败」。
`WARN` 不是最终失败，旧 `ERROR` 也可能已经恢复：后续状态显示在详情/权威任务状态里，
保留原事件级别，不把旧错误悄悄改成成功。

点击行展开结构化详情：事件结果、稳定事件名、明确命名的录制场次/投稿会话 ID、分段和
attempt、原因代码、数值字段、原始诊断。长 stderr 独立折叠并标注截断，不把列表撑高数屏。
详情中的原始内容按普通文本转义，不作为 HTML 执行。

默认采用行内展开，避免抽屉持续压缩日志正文宽度。桌面宽屏以后可增加抽屉，但不能以它
替代窄屏可用的详情。点击「查看本场完整事件」进入场次范围，临时解除冲突的级别/时间/
关键词条件；返回时恢复原筛选和阅读位置，避免只看到错误、漏掉它前后的正常决策。

## 4. 实时追加不能打断阅读

- 默认最新在前，允许切到时间正序查看过程。
- 用户停在列表顶部且未展开详情时可持续跟随；滚离顶部、展开详情或浏览历史后冻结当前
  阅读位置，提示「有 N 条新事件」，点击才插入。不能因新增记录顶走正在看的那一条。
- 「暂停刷新」只暂停页面接收/呈现，不暂停后台任务或日志写入；恢复用游标补齐。
- 断线显示重连状态；历史仍可查看。游标过期或保留期清理导致缺口时明确提示，不假装完整。
- 重复告警按事件类型、场次、分段和原因汇总，展示次数、首末时间和极值。明确区分「界面
  折叠了完整记录」与「来源只保存汇总」；不能提供实际上不存在的原始记录展开。
- 结果为空、筛选无匹配、正在加载、查询失败、持久化异常是不同状态，各有具体文案。

不保留语义含糊的「清空日志」按钮。若需要清空当前显示，明确标作「清空当前显示」；历史
删除属于独立管理操作，不能和阅读操作放在一起。导出范围明确写「当前筛选结果」。

## 5. 运行进度与事件互相跳转

每项显示主播/场次/文件、当前阶段、必要的字节进度/速度、最后更新时间。只有有明确总量的
阶段才显示百分比；预处理未知进度就显示阶段，不伪造全链路完成率。长时间未更新标作过期
快照，避免把断线前的数据当成仍在运行。

进度状态复用已有业务模型，日志页不再实现一份上传状态机。提供「查看本场事件」「查看
失败原因」跳转；补传、取消等操作仍进入既有任务管理页面，不在诊断列表新增危险操作。

## 6. 实现划分和验收

实现时可将页面拆为筛选栏、事件列表/事件行、详情、场次范围、进度视图及查询状态管理；
复用现有 fetch/认证和 Semi 主题。页面组件不解析日志字符串，也不自行推断事件级别。

首轮页面验收：

1. 进入页面能迅速找到红色错误和黄色警告，同时读清主播、文件与具体影响。
2. 级别、业务、主播、时间和搜索联合生效；命中数准确，翻页包含整个查询结果。
3. 一条错误能展开原因并查看前后场次事件，返回保留原筛选和阅读位置。
4. 高频进度不改变事件列表；查看详情、阅读历史时新增日志不抢滚动位置。
5. 360px 窄屏及桌面可读、无横向溢出；深浅色对比清楚，键盘能操作筛选和详情。
6. 初次无日志、筛选为空、断线、日志写入失败、数据被清理、详情截断均有独立状态。
7. 新页不出现文件 tab、文件不存在提示或旧静态 `.log` 下载；保留路由兼容。对照期的
   旧页/原始下载单独保留，直到停旧阶段才改用新库兼容策略。

真实数据、实时连接、分页规模与认证验收随后端实施执行；设计草图只验证界面和本地交互。

## 7. 本轮草图检查

- 用合成数据验证：业务/级别/关键词取交集，详情展开可见技术字段，场次跳转放宽原筛选，
  返回后恢复原条件；运行进度为独立视图。
- 在浏览器核对 736px 和 360px 内容宽度，窄屏无水平溢出，控制台未发现页面运行错误。
- 尚未验证生产 API、真实实时追加或数据持久化；不把原型可点击当作功能已经上线。
