# 11 — 落地独立还原、交叉核对与回归闭环

Status: needs-triage
Blocked by: 10
Phase: P2，之后贯穿 P3–P5
Implementation: not-started

来源：[对比流程](../reconciliation.md)、[报告模板](../templates/reconciliation-report.md)。

## 交付与步骤

1. 将流程整理成可直接使用的三份提示词/输入契约：旧来源独立还原、新原生独立还原、
   结合业务证据交叉核对；两次初始分析互不可见对方结论。
2. 固定问题、证据引用和输出格式；结论必须允许 unknown、pending 和来源不完整，不把
   模型自信程度替代引用。大样本按任务分包，全量清单仍由程序维护。
3. 建合成回归集：预埋丢事件、错分段、单位错误、失败误报成功、两边同缺、轮转缺口，
   同时包含正常文案差异、进度快照/告警汇总等合理差异。
4. 先用确定性校验发现机器可判的错误，再让 Agent 评估解释链和可读性；复核人检查关键
   结论和部分正常案例。P2 单独完成桥接传输报告，原生覆盖记未开始。
5. 为差异建立处置记录和最小回归场景；补契约/调用点/采集/查询或比较规则后重新采包。
   新样本按当前版本重新核对，禁止复用修复前的「通过」。
6. 记录最初一次人工触发的演练结果；后续只有获准才安排运行时周期采样，不在任务中默认
   创建定时器、给 Agent 写权限或自动发布报告。

## 验收

- 合成关键缺口没有被判为通过；不完整来源判证据不足，合理压缩不因行数不同误判缺失。
- 只看到桥接文本时不计原生关键项通过；两边都缺的事实可由预期场景/业务证据暴露。
- 每个结论有来源引用、适用范围及限制；日志内指令保持为不可信数据。
- 至少走通一次「发现差异 → 合成复现 → 修复建议 → 新包复核」闭环；接入原生业务后
   持续复用此能力，不把 P2 的工具演练作为 P3 的覆盖验收。

## 回退与非目标

停止比较不影响采集；修正误判规则须留版本与回归案例。Agent 只读、只建议，不自动修
代码、修改日志配置、写 GitHub 或决定关闭旧系统。
