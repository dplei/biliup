# 15 — 新增事件查询、实时接续和导出 API

Status: needs-triage
Blocked by: 09, 10
Phase: P3，可与业务接入分别推进
Implementation: complete

来源：[总体设计](../spec.md)、[页面设计](../page-design.md)。

## 交付与步骤

1. 复用 08 的仓储，定义有版本约束的列表/详情/诊断接口；按级别、分类、时间、关键词和
   关联 ID 过滤。固定最大页长、稳定游标与索引，计数基于整个查询范围。
2. 默认查询原生事件，桥接诊断显式筛选；返回覆盖范围/来源和持久化健康，避免用户把
   尚未接入的空列表当作没有异常。使用不同列表游标/实时水位含义时在契约中明确区分。
3. 实时流只发布已提交事件；解决历史快照→订阅竞态、断线补查、去重、迟到事件和过期
   游标。无法补齐时明确提示，不静默丢失。
4. 新增按当前查询流式导出 JSONL/CSV，不落长期文件；限制范围/时间/并发，复用脱敏。
   将 10 的内部取证与面向用户的导出区分，不能暴露未授权原始证据。
5. 在实际路由组装处落实认证：列表、流、附件、导出和继续保留的旧日志入口都验证；
   保留部署显式关闭认证的既有语义，不引入另一个默认匿名入口。
6. 用合成大数据和持续写入验证查询计划、内存/超时与录制并发开销，防止长导出阻止
   WAL 回收。旧 `/v1/ws/logs` 暂不映射到新库，保持独立原始对照。

## 验收

- 查询、实时和导出的事件身份/字段一致，持续写入时分页/接续不重不漏。
- 组合筛选与级别计数正确，未知/过期/覆盖不足/存储故障明确区分。
- 启用认证时未登录不能读取任何新旧日志接口/附件/导出；错误文本不泄漏凭据。
- 大数据并发场景满足 06 预算，缓存/页长/附件/导出受限。

## 回退与非目标

停用新 API 或退回旧页面不影响采集；旧协议和旧文件下载此时不废除。
实时协议可在实施时选 SSE 或 WebSocket，但必须遵守同一提交/接续语义。

## Comments

API 可先提供桥接诊断和有限原生样本用于开发，不承诺全覆盖已完成。

- 交付完成、验收 passed，结论见 [P3 回执](../receipts/P3.md)。`/v1/log-events` 系列四个只读
  接口（列表 / 附件详情 / SSE 实时接续 / JSONL·CSV 导出）落在登录守卫内的 router 里，
  默认只查原生事件，桥接需显式 `capture_kind=legacy_bridge`，响应带覆盖范围、保留水位与
  采集健康——采集关闭时明确返回 `availability=disabled`，不给一个会被误读为「没有异常」的空列表。
- **行为变更**：旧的 `/v1/ws/logs` 从 `app.rs` 守卫之外挪进 router，开启 `--auth` 后未登录
  不能再读旧日志文件流；显式关闭认证的部署行为不变。实跑证据：守卫态五个入口全 401，
  关闭态列表/导出/实时 200、附件 404、旧 ws 400（需要 upgrade，行为未变）。
- 事件库加了 `capture_kind` 与 `message` 两列（加法迁移并从 payload 回填），否则按采集种类
  和关键词过滤只能全表扫 JSON。旧版本写出的库仍可查。
- 未做：导出的并发上限、WAL 回收的量化观测；旧 `/v1/ws/logs` 仍读真实旧文件，不映射新库。
