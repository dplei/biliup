# 09 — 在旧体系旁接入新采集，保留原始对照

Status: needs-triage
Blocked by: 08
Phase: P2
Implementation: not-started

来源：[并行边界](../rollout-plan.md)。主要入口见 `stream-gears/src/server.rs`、
`biliup-cli/src/main.rs`、`stream-gears/src/lib.rs`，具体受支持范围以 06 清单为准。

## 交付与步骤

1. 增加新采集开关，默认关闭；记录开关/过滤配置在启动时还是运行时生效，不承诺热重装
   subscriber。入口只组合一次 subscriber，新旧消费者分别持有明确生命周期。
2. 将旧 tracing 事件旁路转入新库，标为 `legacy_bridge`，保留真实来源与缺字段说明。
   不给自由文本制造稳定业务 event_name，不把桥接称作原生结构化覆盖。
3. 验证旧文件、控制台、过滤规则和旧页面输出继续工作；原生测试事件不混入旧对照，
   新采集过滤不依赖旧总 EnvFilter。任何旧输出必要变化登记基线版本。
4. Rust/wheel 的 server 与非 server、Python 局部宿主分别接入；非 server/嵌入式数据库
   持久化显式选择、可不启用；多次调用和已有 subscriber 不 panic、不重复消费事件。
5. 将新存储健康作为独立可读取状态，禁用新链后旧链仍能运行；观察新旧合计资源占用。
6. 在本地受控环境启用一次完整试点，包括新库不可用与关闭新链的演练；不删旧文件。

## 验收

- 新采集关闭时旧行为符合基线；开启时两份来源都存在，原始旧文件仍是真实来源。
- 新库失败不导致旧 sink 停止，旧文件失败也不被新系统错误报告为完全健康。
- 桥接事件可查询且不会假称已知场次/分段；覆盖范围、过滤和丢弃状态可导出。
- 各支持入口的初始化/重复调用/退出通过；正常负载满足 06 合计预算。

## 回退与非目标

关闭新采集即可恢复旧模式，记录是否需要安全重启；不得为日志切换强杀运行任务。
不减少旧进度 INFO、不替换旧 WebSocket/下载、不默认切新页面。

## Comments

桥接只是建立第二条可观测链路，后续必须逐条补原生语义。
