# 07 — 建立不依赖业务的通用事件组件

Status: ready-for-agent
Blocked by: 06
Phase: P1
Implementation: complete

来源：[实施计划](../rollout-plan.md)、[事件模型](../spec.md)。

## 交付与步骤

1. 建立公共 Rust 组件（可采用独立 crate，落位时检查 workspace 依赖方向），提供事件
   类型、受控字段、发射接口、上下文和初始化/关闭 handle；不得依赖 server 业务模块。
2. 实现 tracing 采集 Layer：处理 `on_new_span`、`on_record`、父子作用域和事件字段覆盖，
   在回调时生成不可变快照。保留来源类型，禁止从自由文本猜关联。
3. 实现字段允许列表、单位/长度约束、中文摘要和有界错误/附件描述；脱敏发生在任何新 sink
   输出前，不因为桥接来自旧日志就跳过脱敏。
4. 事件经按条数/字节双限的队列交给可替换消费者；提供 dropped、队列深度和健康接口。
   发射路径无 SQL、网络等待，不序列化无界对象。消费者可先用测试内存仓储。
5. 设计独立过滤和路由，使旧过滤配置不误伤新 INFO/WARN，也能让原生事件避开旧 sink。
6. 明确异步/阻塞任务、Actor/channel 和回调的上下文载体及宿主生命周期；off 时避免昂贵
   字段构造，关闭时限时排空。仅用合成调用者，不接现有应用入口。

## 验收

- 不启动 Web 服务、没有业务数据库，也能构造、采集并读取合成事件。
- 覆盖延迟补 span 字段、嵌套覆盖、spawn/回调交错；旧事件快照不随分段切换而改变。
- 队列满或消费者失效不会无限等待、越过内存预算或递归自记日志；丢弃计数可见。
- 敏感字段/长错误链/换行输出按契约处理；event_uid 的重投身份与不同事件身份可区分。
- 输出能力有必要的单元/并发测试；不是只断言实现常量。

## 回退与非目标

旧入口尚未接入，组件失败不改变现有行为。暂不修改业务日志级别、不处理前端，也不安装
第二个全局 subscriber。
