# 03 — 分离进度，补齐决策与分级语义

Status: needs-triage
Blocked by: 01

来源：[spec](../spec.md)。仅拆分，尚未实现。

## 范围

- 复用 `UploadActivity`、`persist_attempt_progress`、attempt 阶段与心跳。
- 移除或降为默认不持久化的 DEBUG：逐块进度 INFO 与重复无变化的扫描消息。
- 不改变每次已确认分块驱动 watchdog 的语义；UI 推送节流独立于业务活性判断。
- 规范开始/完成/失败事件，修复、预处理、补传、投稿等关键决策记录结果与原因。
- 区分预期跳过、可恢复异常与本次失败；对高频同类告警设计首条+有界汇总。

## 验收

1. 上传分块数增长时，普通日志不随分块数线性膨胀，进度快照和阶段仍更新。
2. 预处理、排队、传输的 heartbeat/watchdog 原有边界保持不变。
3. 正常执行、配置关闭、失败 fallback、资格拒绝等路径均有稳定决策事件。
4. 告警汇总保留计数、首末时间、极值；换分段/原因后重新记录，不吞掉新异常。

## Comments

可在日志库落地前先改善控制台语义；不是只在前端过滤进度字符串。
