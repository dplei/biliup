# 02 — 独立日志库、批量写入与故障边界

Status: needs-triage
Blocked by: 01

来源：[spec](../spec.md)。仅拆分，尚未实现。

## 范围

- 建立日志存取接口，第一版实现独立 SQLite 连接与独立 migrations，业务池不变。
- 增加 `log_event`、有界 `log_diagnostic`；固定索引列与扩展 JSON 分开。
- tracing Layer 合并字段后入有界队列，后台批量写；控制台与数据库分别过滤。
- 处理启动缓冲、优雅退出、重试幂等、丢弃计数、递归日志防护和数据库健康状态。
- 审计的事务持久化/投影与普通尽力保存的诊断日志分开，不承诺跨库原子事务。
- 实施时间/字节保留上限、低水位清理、checkpoint、一致性备份和受控空间回收。

## 验收

1. 正常重启可查询已提交事件；`event_uid` 重投不生成重复记录。
2. 模拟忙锁、只读、满盘、队列溢出与强杀，准确暴露损失/延迟边界；日志故障不阻塞业务。
3. DEBUG 配置和数据库写入故障不会形成日志递归；关闭控制台 INFO 不影响数据库 INFO。
4. 长 stderr 捕获和存储均受限；正常事件列表不拉取附件正文。
5. 清理遵守优先级，审计不被普通日志 TTL 删除；备份可独立恢复验证。

## Comments

首版只需 SQLite，不把 PostgreSQL 驱动或云采购作为完成条件。
