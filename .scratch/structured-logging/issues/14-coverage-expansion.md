## 交付与步骤

1. 按 06 的入口/下载路径表逐项补原生观测，覆盖外部工具和其余下载器；分批接入，不能
   把「桥接看到了文本」当作业务字段已完成迁移。
2. 补齐系统启动/退出、认证健康变化、关键人工操作与恢复审计。系统无主播上下文时
   使用进程身份；CLI 用 task 身份，嵌入式调用用宿主拥有的生命周期。
3. 核对已有 durable 审计：留在业务事务；需要展示的记录通过稳定 event_uid 幂等投影。
   如有必须可靠保存的事实尚无业务持久化，明确设计业务事务/outbox 的增量任务，不用
   通用日志尽力写入伪装为完成，也不删除既有恢复账本。
4. 检查每条路径的外部 stderr 有界采集/退出码/首个错误，以及 HTTP 请求/凭据脱敏，
   页面默认不展示第三方诊断洪流；桥接仍可显式查询。
5. 剩余调用点只做加法式接入：保留原日志、原返回值和原业务控制，新采集失败必须与业务
   隔离。本地门槛为格式/编译、基本启动与关闭新采集后路径不受影响；Rust CLI、wheel CLI、
   Python 下载/上传的正常、错误、多次调用和退出案例转入实际双写观察，不再预先穷举矩阵。
6. 完成适用关键覆盖项及未迁移诊断的分类清单：保留桥接、无需持久化或显式不支持须有
   理由。源码调用点闭合并通过最低运行门槛后即可启动第一轮完整观察；所有关键项最终仍须
   由原生/指定权威源回答，未自然触发的低频路径保持待观察而不是补造通过。

## 验收

- 所有承诺支持的入口和业务域都有原生调用点；实际触发后有旧日志与新事件两份独立证据，
  未运行的路径保持待观察、不提前写成通过。
- 实际运行中出现的正常、并发和异常样本完成双源核对；不再要求上线观察前完成人工异常矩阵，
  但桥接未迁移部分仍不能掩盖关键原生缺口。
- 审计回放幂等且不会随普通日志清理消失；普通日志故障不改变任务恢复行为。
- 整体资源/隐私/只读比较符合基线，旧链仍保留；第一轮观察的报告和差异处置可审阅。
