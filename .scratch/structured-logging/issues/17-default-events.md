# 17 — 新页面成为默认，旧日志继续观察

Status: needs-triage
Blocked by: 11, 14, 16
Phase: P4
Implementation: not-started

来源：[切换门槛](../rollout-plan.md)、[对比流程](../reconciliation.md)。

## 交付与步骤

1. 汇总所有支持入口、覆盖清单、故障/隐私/资源验证与第一轮完整双写报告。关键缺失、
   关联错误或来源不足尚未关闭时停止本任务，不用页面完成度替代数据验收。
2. 使用 16 预先实现的开关，将 `/logviewer` 默认改为新事件页，主导航改为「日志与事件」；
   提供明确的「旧日志」入口，继续读原文件。页面默认与新采集、旧文件开关分开；若仍需
   代码变更，先完成改动再重新累计观察，不能沿用旧构建成绩冒充同版本验证。
3. 新入口下载走查询导出；旧入口仍提供原始对照，开发者设置区分新/旧采集，避免一个
   级别配置同时压低两边的覆盖。展示有效配置及是否需重启。
4. 演练只回退页面默认而不中断采集，再演练新链故障时使用旧链诊断；保证认证边界一致。
5. 维持完整双写，完成第二轮完整观察并使用 Agent/确定性校验持续核对。两轮计数须满足
   同一最终版本、目录和关键配置；修复关键问题后按计划重新验证。
6. 出具建议是否停旧写入的报告，保留不足项、回退步骤和实际日志容量，不自动进入 18。

## 验收

- 新默认可读、可查、进度独立；旧原始来源仍可访问，未替换成新库文本投影。
- 两轮完整观察和全场景检查满足计划门槛，无未处理关键差异；样本数/天数不是唯一依据。
- 页面和采集可分别回退，普通用户不误读旧错误为当前失败，空数据不掩盖覆盖/健康问题。
- 实测资源预算包含两套存储；相关报告/回退步骤可审阅后才申请执行停旧阶段。

## 回退与非目标

默认切回旧页面，保留新库与双写；如采集有问题再关闭相应新链。此阶段旧文件不停止写入，
旧日志正文不重写/降噪；不通过启动 P5 来降低双写开销。

## Comments

后续已获阶段发布授权时按证据执行；本计划不是部署请求，也没有创建自动晋级任务。
