# 07 — 计划内主动换连接：零缺口切换

Status: needs-info
Blocked by: 05

## 前提

仅当 [`05`](./05-upstream-lifetime-experiment.md) 确认根因是**上游连接寿命上限**（假设 A）时立项。
若 `05` 判定为「分段动作触发断连」（假设 B），本 ticket 不成立——那种情况下要修的是分段路径本身，
换连接只是给自制的问题打补丁。

取代 [`06`](./06-make-before-break.md)（双读方案，已 `wontfix`）。

## 核心思路

不等连接死、也不等停顿超时判死，而是在连接活到阈值时**主动关闭并立刻重建**。
关键在于：主动切换时我们*知道*要断，因此 `01` 的停顿超时（7~8 秒）这一段直接归零。

## 为什么单连接就能零缺口

三条实测数据（[`findings-cdn-behavior.md`](../findings-cdn-behavior.md) 第 3~5 节）：

1. 新连接握手即给关键帧，**起点对齐到当前 GOP 的起点**；
2. GOP 实测固定 **2.0 秒**；
3. 建连到首字节 **0.10~0.14 秒**。

旧连接的断点必然落在当前 GOP 内部。只要新连接在一个 GOP（2.0s）内建好——实测余量约 14 倍——
它的起点就必然 **≤** 旧连接的断点。

实测直接验证了这一点：在两个房间上测得切换点分别是 **2.133s 与 1.300s 的重叠**，两次都是重叠、
没有一次是缺口。**零缺口是结构性保证，不是运气。**

## 改动范围

### 触发

- 新增可配置阈值（基于 `Connection::started_at`，建议默认 **关闭**，灰度开启）；
- 值应明显小于观测到的连接寿命下限（原房间为 1817s，建议起步 1750s，留 ~70s 余量）；
- 若上游在阈值前就自然断连，走既有路径（`01` + `04`），不亏。

### 切换

1. **在关键帧边界切**：等收到一个关键帧、缓存刷完后再关闭旧连接，使旧文件以完整 GOP 结尾；
2. 关闭旧连接，立即建立新连接（复用 `04` 的候选快路径，跳过 `check_stream`）；
3. 新连接的首个关键帧即为续写起点。

### 去重（本 ticket 唯一的新逻辑）

切换点会有 0~2 秒重叠。因为时间戳是**流级绝对基准**（实测第 2 节），判据极简单：

```
if tag.header.timestamp <= last_written_timestamp { skip }
```

落点与 `httpflv.rs` 现有的非单调 DTS 告警是同一处，不需要新的时间戳管理机制。

### 不要做的事

- **不要重写时间戳基准**。跨连接天然对齐，重写只会引入 bug。
- **不要因此切换线路或让旧线路冷却**。实测 4 条记录横跨 4 台不同 CDN 主机、寿命一致，
  说明寿命是**连接维度而非线路维度**；同一主机重开一条连接即可。
  冷却线路会把健康线路误踢出候选池，并污染 `route_health` 的熔断记账
  （与 `04` 划的是同一条边界：快路径只管「怎么重连」，不管「线路健不健康」）。
- **切换点即分段点**，不要额外产生分 P。

### 回落

新连接建立失败 → 回落到既有路径（重新 `check_stream` + 正常退避），并正常计入 `route_health`。
这是本方案相对 `06` 唯一的下行风险；`01` 的停顿超时仍是最后兜底。

## 验收标准

1. 单测：给定「旧连接断点 + 新连接从更早的 GOP 起点开始」的双流字节序列，
   断言输出时间戳单调、无重复关键帧、无内容缺失。
2. 单测：新连接建立失败时，输出与不启用该特性时逐字节一致。
3. 单测：切换不产生额外分 P。
4. `cargo test -p biliup -p biliup-cli` 全绿。

生产验收：

5. 开启后连续 3 场，`03` 的 `total_gap_ms` 在切换点为 **0**。
6. 日志可见去重发生（丢弃的重叠 tag 数 > 0），且分 P 数量符合预期。
7. 回落路径至少被触发观测到一次（可人为制造），确认不产生额外缺口。

## 风险

- **新连接建不起来** → 变成真缺口。实测建连 0.14s、成功率待观察；`01` 兜底。
- **切换时上游恰好在改码率/重启转码** → 新连接的 seq header 可能与旧的不一致。
  切换前应比对 AAC/H264 sequence header，不一致就放弃本次切换、退回自然断连
  （同一文件内更换 SPS/PPS 会让部分播放器与转码链路出问题）。
- 阈值设置依赖对该房间连接寿命的观测；寿命若不稳定，切换可能白做（但不亏）。
