# 代码索引维护约定

根目录 [`CODE_INDEX.md`](../../CODE_INDEX.md) 是供后续 agent 和维护者先行查阅的文件级导航。
它补充代码图索引，不替代源码、类型系统或 ADR。

## 检索顺序

1. 先在 `CODE_INDEX.md` 中按领域词、路径片段或符号名定位入口。
2. 命中时从列出的文件和关键符号开始阅读；需要确认调用链或影响面时，再用
   `codebase-memory-mcp`。
3. 未命中时使用代码图检索；仅在精确字面量、刚修改的代码或代码图无结果时回退 `rg` 等
   本地搜索。

索引是增量的。没有条目只表示该文件尚未被沉淀，不表示它不重要或不存在。

## 何时更新

满足下面两点时，在当前任务收尾前新增或修订条目：

- 本轮已经实际阅读到足以确认文件的主要职责和关键符号，而不是只从文件名猜测；
- 该文件是功能入口、流程编排、核心实现、共享边界或其他以后值得直接跳转的位置。

以下内容通常不单独收录：生成物、第三方代码、锁文件、静态资源、机械式声明、一次性 fixture，
以及只为“把索引补全”而额外扫描到的文件。普通测试文件放在对应生产文件的说明中即可；只有
承担特殊集成边界或事故回归入口的测试才单独列出。

不要在无关任务中做全仓盘点。这个索引应随真实工作路径自然生长。

## 文件条目格式

按稳定的领域或子系统分组，使用三列表格：

```md
| 文件 | 主要作用 | 关键符号 |
| --- | --- | --- |
| `path/to/file.rs` | 一句话说明它负责什么，以及不负责什么（必要时）。 | `TypeName`、`entry_fn` |
```

- “主要作用”保持一句话，描述行为或边界，不复述文件名。
- “关键符号”只列最适合进入该文件的 1–5 个类型、函数或导出；没有稳定符号时写 `—`。
- 不写易漂移的行号、更新时间、完整 API 清单、实现步骤或任务历史。
- 同一路径只出现一次。内容变化时就地修订，不追加第二份摘要。
- 只记录已由源码确认的事实；不确定的推断不要写入。

## 关系格式

文件职责与文件关系分区维护，避免在每个摘要里交叉重复。关系使用单向边：

```md
- `caller.rs` → `callee.rs`（`symbol`）：这条边承载的控制流、数据流或边界。
```

只记录能帮助决定“下一步该读哪个文件”的高信号关系，例如进程入口、核心流程委派、持久化
边界和跨语言桥接。普通 `use` / `import`、同目录的显然依赖和反向重复边不记录。一条关系只在
最自然的方向出现一次。

## 保持可用

- 修改、移动或删除已收录文件时，同步修订对应条目和关系。
- 新条目放入已有领域；没有合适领域时再新建小节，不按任务名建小节。
- 不用 Mermaid 维护完整调用图；精确调用关系交给代码图工具，索引只保留导航所需的少量边。
- 当某个领域超过约 40 个条目或根索引接近 500 行时，把该领域拆到
  `docs/code-index/<area>.md`，根索引仅保留领域说明、首要入口和链接。
- 变更索引属于代码探索或实现的正常收尾，不需要单独创建 issue。

更新后运行：

```bash
python3 scripts/check_code_index.py
```

校验器会拒绝不存在或逃出仓库的路径、重复文件条目、重复关系，以及关系中尚未建立文件摘要
的端点。它不校验自然语言摘要和符号语义；这些仍以本轮实际阅读的源码为准。
