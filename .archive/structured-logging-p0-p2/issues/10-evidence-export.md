# 10 — 实现有界、只读的双源证据导出

Status: needs-triage
Blocked by: 09
Phase: P2
Implementation: complete

来源：[对比流程](../../../.scratch/structured-logging/reconciliation.md)。本任务无需等待新网页完成。

## 交付与步骤

1. 建本地只读 CLI/脚本，按受控场景或任务清单选择样本，不从「已经存在的事件」反推
   全部任务。输出到不入库目录，不向应用新增长期 `.log` sink。
2. 导出真实旧文件的固定片段，记录轮转代次/字节边界与校验信息；遇截断、删除、轮转或
   无法稳定读取要标明不完整。读取过程不移动/修改源文件。
3. 从新库固定已提交高水位分批短读，原生/桥接分别导出；保留迟到事件、排空宽限、补包
   机制。只读提取所需业务快照/已有历史，不复制整个业务库或假设跨库原子快照。
4. 生成 manifest：版本、范围、配置、覆盖、过滤、健康、各源时区/边界/截断和未知项。
   无法拼成同一完整观察范围时给出机器可读的不足状态。
5. 交给 Agent 前脱敏并做批内一致匿名映射；有界读取附件，验证导出换行与 JSONL 可解析。
6. 添加确定性校验：事件身份、契约字段/单位、引用完整性和已知场景关联，输出引用可回查
   的错误。比较模式只读凭据与文件，禁止数据库写操作。

## 验收

- 同一个固定证据包可以重复分析；导出期间新增事件不让页边界重复/漏读。
- 轮转、迟到、强杀缺口、附件过期、导出超限均能报告不完整，不能误标全量成功。
- 原生和桥接分开；P2 桥接核对不能伪装成业务迁移已完成。
- 含凭据、签名 URL、超长错误和恶意指令的合成数据不会泄漏或执行；真实映射不进公开目录。
- 导出负载满足 06 预算；不持有长读事务妨碍 WAL 回收，不改变业务状态。

## 回退与非目标

停止导出器即可，不影响两套采集。保留失败 manifest 便于重采，不通过删源日志腾空间。
不创建自动上传、外部数据库同步或后台巡检计划。

## Comments

稳定来源引用与完整性状态是 Agent 对比能否可信的前提。

本阶段验收结论见 [P2 回执](../receipts/P2.md)：6 个证据包（5 入口 + dev server 真实服务）
completeness 均 complete、确定性校验 passed；轮转、迟到补包、保留裁剪、异常关闭窗口、附件缺失、
预算超限均能报不完整；凭据/注入文本不泄漏且批内别名一致；导出期间源文件与事件库字节不变。
