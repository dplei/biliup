# 06 — 冻结事件契约、旧来源基线和验收口径

Status: ready-for-agent
Blocked by: —
Phase: P0
Implementation: complete

来源：[实施计划](../../../.scratch/structured-logging/rollout-plan.md)。本任务是建议的首个实施任务，不表示本轮已执行。

## 交付与步骤

1. 从 `CODE_INDEX.md` 定位三个 Rust 日志初始化位置及所有支持的命令/下载路径，逐一记录
   subscriber 所有者、旧 sink、过滤配置、时间精度、退出处理和读取入口。
2. 完成 [覆盖清单](../../../.scratch/structured-logging/coverage-ledger.md) 的 v1：每个关键事实列出旧调用点、原生事件名、
   适用入口、必填/允许未知字段、单位、结果/原因枚举及一对多映射。不是批量重写调用点。
3. 冻结基础 schema：事件身份、时间、级别/分类、上下文、脱敏/截断，以及
   `capture_kind=native|legacy_bridge`；普通诊断、进度和 durable 审计各自明确来源。
4. 定义旧输出保持项和新事件路由规则；新原生事件不得污染旧对照，安全脱敏改动单独记账。
5. 在本地受控数据下采旧系统基线，冻结采集开销、业务延迟/连续性、内存、数据库/附件/WAL
   和双写总磁盘预算；明确采样方法和数字门槛。尚无实测数字时不得直接宣称允许开启试点。
6. 建立合成验收场景目录：正常链、双路交错、切片/重连、预处理跳过/降级、失败后恢复、
   投稿等待/不确定、重启、过滤变化、存储故障。证据引用可脱敏复用。

输出是更新后的契约/覆盖清单与预算、场景说明；真实运行证据只放不入库目录。

## 验收

- 每项关键事实都有适用条件和证据来源，未覆盖路径显式列出，没有「从时间猜出 ID」。
- 先有观察窗口、资源上限和判定规则，再采验收样本；参数不根据结果临时放宽。
- 已明确录制场次、投稿会话、分段与 attempt 的不同身份；独立命令不伪造主播信息。
- 旧业务和日志行为保持不变；仅完成契约、基线与受控检查。

## 回退与非目标

本任务无运行时切换。发现未知路径就补清单，不通过删掉该路径的要求来解阻。
不采购云服务、不默认访问生产、不发布任何真实样本。
